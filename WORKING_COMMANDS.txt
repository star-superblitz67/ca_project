================================================================================
📊 GTKWAVE SIGNAL NAVIGATION (Once Window Opens)
================================================================================

After running "gtkwave mips_waveform.vcd wave.do", you'll see signals grouped:

1️⃣ CLOCK & RESET
   └─ clk, rst_n

2️⃣ PIPELINE STAGES (Watch Instructions Flow)
   ├─ if_id_instr    (IF/ID register - instruction in decode)
   ├─ id_ex_instr    (ID/EX register - instruction in execute)
   ├─ ex_mem_instr   (EX/MEM register - instruction in memory)
   └─ mem_wb_instr   (MEM/WB register - instruction in writeback)

3️⃣ PROGRAM COUNTER PROGRESSION
   ├─ pc             (Current PC)
   ├─ if_id_pc       (PC in IF/ID stage)
   ├─ id_ex_pc       (PC in ID/EX stage)
   ├─ ex_mem_pc      (PC in EX/MEM stage)
   └─ mem_wb_pc      (PC in MEM/WB stage)

4️⃣ HAZARD & FORWARDING RESOLUTION
   ├─ forward_a      (Operand A source: 2'b10=EX, 2'b01=MEM, 2'b00=RF)
   ├─ forward_b      (Operand B source: same encoding)
   ├─ load_use_hazard (1 = stall pipeline for load-use)
   ├─ ex_mem_rd      (Destination register from EX/MEM)
   └─ mem_wb_rd      (Destination register from MEM/WB)

5️⃣ CONTROL SIGNALS
   ├─ if_stall       (1 = L1I cache miss, freeze IF stage)
   ├─ mem_stall      (1 = L1D cache miss, freeze MEM stage)
   ├─ pc_write       (1 = allow PC increment)
   ├─ if_id_write    (1 = allow IF/ID update)
   └─ id_ex_flush    (1 = flush on branch)

6️⃣ CACHE REQUESTS
   ├─ if_cpu_addr[31:0]    (Instruction fetch address)
   ├─ if_cpu_read          (Instruction read request)
   ├─ mem_cpu_addr[31:0]   (Data memory address)
   ├─ mem_cpu_read         (Data read request)
   ├─ mem_cpu_write        (Data write request)
   ├─ mem_cpu_wdata[31:0]  (Data being written)
   └─ mem_cpu_rdata[31:0]  (Data being read)

7️⃣ REGISTER FILE
   └─ rf[0] through rf[10]  (Scroll down to see register values)

8️⃣ ALU OPERATIONS
   ├─ id_ex_alu_op[3:0]   (0=add, 1=sub, 2=and, 3=or, 4=slt)
   ├─ ex_mem_alu_out[31:0] (ALU result)
   └─ mem_wb_mem_rdata[31:0] (Loaded data or ALU result)


================================================================================
🔍 WHAT TO LOOK FOR IN WAVEFORM
================================================================================

✓ Cache Hits (Cycles 0-20):
  - All instructions execute each cycle (no stalls)
  - if_stall = 0, mem_stall = 0
  - if_id_instr updates every cycle
  - Register file changes on writes

✓ L1I Cache Miss (Around Cycle 50-70):
  - if_stall = 1 (goes HIGH)
  - if_cpu_addr holds steady
  - if_id_instr doesn't change
  - Pipeline IF stage frozen
  - After ~10+ cycles: if_stall drops, instruction fetched

✓ L1D Cache Miss (Around Cycle 100-120):
  - mem_stall = 1 (goes HIGH)
  - MEM stage freezes
  - mem_cpu_addr holds steady
  - IF/ID/EX stages continue (if hitting L1I)
  - After ~10+ cycles: mem_stall drops, data loaded

✓ Forwarding Active (Cycle 30-40):
  - forward_a or forward_b = 2'b10 or 2'b01 (not 2'b00)
  - Operand value appears immediately from EX/MEM or MEM/WB
  - No stall needed (RAW hazard resolved)

✓ Load-Use Hazard (Around Cycle 25):
  - load_use_hazard = 1
  - pc_write = 0, if_id_write = 0
  - PC doesn't increment next cycle
  - Pipeline freezes for 1 cycle
  - After 1 cycle: load_use_hazard = 0, pipeline resumes

📋 MIPS INSTRUCTIONS BEING EXECUTED (in testbench)
================================================================================

The testbench (tb_system.sv) generates a sequence of instructions:

  ADD  $1, $2, $3      (R-type: $1 = $2 + $3)
  ADDI $4, $1, 100     (I-type: $4 = $1 + 100)  ← Can trigger forwarding
  LW   $5, 0($4)       (Load from memory)        ← Can trigger load-use
  SW   $5, 4($4)       (Store to memory)
  BEQ  $1, $2, label   (Branch if $1 == $2)
  SUB  $6, $3, $4      (R-type: $6 = $3 - $4)
  ... (repeated with various addresses to trigger cache misses)

================================================================================
⚙️ KEY SIGNALS FOR DEMO/VIVA EXPLANATION
================================================================================

Signal Hierarchy (explain in this order):

1. PC Progression:
   "Watch if_id_pc increment by 4 each cycle (normal) or stay constant 
    (when if_stall=1 due to L1I miss). This shows instruction fetch control."

2. Instructions Through Pipeline:
   "Follow if_id_instr → id_ex_instr → ex_mem_instr → mem_wb_instr.
    Each should have a 1-cycle delay. If stalled, instruction halts."

3. Forwarding (RAW Hazard):
   "When forward_a/forward_b = 2'b10, data is forwarded from EX stage.
    Without forwarding, this would stall. Shows hazard resolution."

4. Load-Use Hazard:
   "After LW instruction, next ALU operation stalls (load_use_hazard=1).
    Pipeline waits 1 cycle for data from memory."

5. Cache Misses:
   "if_stall=1 when L1I misses. mem_stall=1 when L1D misses.
    Watch memory addresses propagate to L2 and DRAM."

6. Register Updates:
   "rf[1], rf[4], rf[5] show computed values appearing in WB stage.
    LW results appear after data loads from cache."


================================================================================
❓ TROUBLESHOOTING
================================================================================

"Compilation fails - syntax errors"
  → Ensure iverilog v11+: iverilog --version
  → Check Icarus Verilog compatibility (no dynamic arrays in always blocks)

"Waveform shows all 'x' (undefined)"
  → Simulation may not have run long enough
  → Ensure mips_waveform.vcd was generated (check file size > 10KB)
  → Verify testbench runs to completion (check $finish message)

"GTKWave window won't open"
  → Verify GTKWave installed: gtkwave --version
  → Try opening manually: gtkwave mips_waveform.vcd (without wave.do)

"Too many/wrong signals visible"
  → wave.do pre-configures signal hierarchy
  → Can customize by editing wave.do or manually adding signals in GTKWave

"Simulation runs but shows random values"
  → Check rst_n signal initializes properly
  → Verify testbench has sufficient clock cycles ($finish at 2505000)
